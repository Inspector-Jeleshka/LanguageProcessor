## 1. Общее задание

### 1.1 Исходный код

```c
#include <stdio.h>

int square(int x) {
  return x * x;
}

int main() {
  int a = 5;
  int b = square(a);
  printf("%d\n", b);
  return 0;
}
```

В коде определяется функция square, вычисляющая квадрат полученного числа. В main вызывается square для значения 5 и выводится результат.

### 1.2 Получение AST

Команда для генерации AST:
`clang -Xclang -ast-dump -fsyntax-only main.c`

<img width="1026" height="766" alt="Изображение AST" src="https://github.com/user-attachments/assets/164100e6-6137-4f20-949a-319a512b0213" />

В AST функция square представлена узлом FunctionDecl, параметр x — узлом ParmVarDecl, а выражение x * x — узлом BinaryOperator.

### 1.3 Генерация LLVM IR

LLVM IR до оптимизаций:  
`clang -O0 -S -emit-llvm main.c -o main_O0.ll`  
<img width="1022" height="768" alt="LLVM IR до оптимизаций" src="https://github.com/user-attachments/assets/7f67260e-2d6a-4fe9-a3b0-78efebcc3308" />

LLVM IR после оптимизации -O2:  
`clang -O2 -S -emit-llvm main.c -o main_O2.ll`  
<img width="1024" height="766" alt="LLVM IR после оптимизаций" src="https://github.com/user-attachments/assets/fc90be1d-72c5-426b-b275-7866d5de3c69" />

В IR до оптимизаций присутствуют инструкции alloca, store, load, а функция square вызывается отдельно.  
После оптимизации -O2 код становится короче: компилятор удаляет лишние инструкции, может встроить функцию square и упростить вычисления.

#### Сравнение IR

Команда сравнения:  
`diff -u main_O0.ll main_O2.ll > main_diff.txt`

<img width="1026" height="766" alt="diff main_O0 main_O2" src="https://github.com/user-attachments/assets/3f683868-3ac9-40b9-aef9-eda8c91292a6" />

После оптимизации уменьшается количество инструкций, исчезают лишние обращения к памяти, а вычисления упрощаются.

### 1.4 Построение CFG

Команда для генерации .dot-файлов CFG для функций до оптимизаций:  
`opt -passes=dot-cfg -disable-output main_O0.ll`

## 2. Индивидуальное задание

### 2.1 Исходный код

Вариант 2.7 Вещественные константы

```c
const double PI = 3.141592653589793;

int main() {
  double r = 2.0;
  double area = PI * r * r;
  return (int)area;
}
```

### 2.2 Получение IR -O0

Используемая команда:  
`clang -O0 -S -emit-llvm main.c -o main_O0.ll`

<img width="1026" height="606" alt="main_O0.ll" src="https://github.com/user-attachments/assets/1230273b-305c-4a67-aed7-c53104098022" />

### 2.3 Получение IR для -O2

Используемая команда:  
`clang -O2 -S -emit-llvm main.c -o main_O2.ll`

<img width="1028" height="392" alt="main_O2.ll" src="https://github.com/user-attachments/assets/19008c6c-934f-4ec5-ad24-b5dec50b8426" />

Произошло свертывание константы - всё вещественное выражение и последующее преобразование к int вычислены компилятором, поэтому в итоговом IR остаётся только `ret i32 12`.

### 2.4 Сравнение CFG

CFG программы до оптимизаций:  
<img width="507" height="349" alt="cfg_main_O0.png" src="https://github.com/user-attachments/assets/7a0cc927-e74c-4e3b-b7fb-a6c78ce11ab3" />  
CFG программмы после оптимизаций:  
<img width="258" height="106" alt="cfg_main_O2.png" src="https://github.com/user-attachments/assets/46f1ffa3-f5c8-4243-aa03-bc34f64ae8a1" />

При *-O0* и *-O2* CFG функции main состоит из одного базового блока, поскольку программа не содержит ветвлений и циклов.
При *-O0* в блоке сохраняются операции вычисления `PI * r * r` и преобразования результата к int,
а при *-O2* они заменяются одной инструкцией `ret i32 12`.

### 2.5 Вывод

В ходе работы был получен и исследован LLVM IR программы с вещественной константой `PI`.
При *-O0* константа `PI` уже известна компилятору, однако операции умножения и преобразования результата к int сохраняются в IR.
При *-O2* всё выражение `PI * r * r` вычисляется во время компиляции, поэтому функция main упрощается
до возврата константы `12`. CFG в обоих случаях состоит из одного базового блока, но при *-O2* его
содержимое значительно упрощается.

1. Clang — это фронтенд компилятора для языков семейства C. Он анализирует исходный текст, строит AST,
  проверяет корректность программы и формирует LLVM IR для дальнейшей обработки.
2. LLVM — это инфраструктура компилятора, использующая универсальное промежуточное представление LLVM IR.
  На его основе выполняются анализ, оптимизации и генерация машинного кода для различных архитектур.
3. AST отражает синтаксическую структуру исходной программы: объявления, выражения и операторы языка C.
  LLVM IR является более низкоуровневым представлением, ориентированным на выполнение, оптимизацию
  и последующую генерацию машинного кода.
4. IR необходимо для разделения анализа исходного языка и генерации кода. Благодаря этому одни и те же оптимизации
  могут применяться к программам на разных языках и для разных целевых платформ.
5. Инструкция alloca выделяет память под локальный объект в стеке текущей функции. В неоптимизированном IR она
  используется для хранения локальных переменных, например r и area.
6. Оптимизация кода нужна для повышения эффективности программы: уменьшения времени выполнения,
  сокращения размера кода и удаления лишних вычислений. В исследуемой программе оптимизация позволяет
  заранее вычислить площадь и вернуть готовое значение 12.
7. SSA-форма — это представление, в котором каждому временному значению присваивается результат только один раз.
  Она облегчает распространение констант, удаление неиспользуемых вычислений и другие оптимизации.
8. CFG — это граф потока управления, вершинами которого являются базовые блоки, а рёбрами — возможные переходы между ними.
  Он позволяет анализировать порядок выполнения инструкций, ветвления и циклы.
9. Арифметические операции в LLVM IR представлены отдельными инструкциями. Например, для вещественного умножения
  используется fmul, для целочисленного сложения — add, а для вещественного сложения — fadd.
10. Функции являются отдельными единицами анализа и оптимизации, поскольку каждая функция имеет собственные параметры,
  локальные значения, базовые блоки и CFG. Это позволяет независимо оптимизировать её тело и затем применять
  межпроцедурные преобразования.
11. Если короткая функция вызывается один раз, компилятор может выполнить встраивание: заменить вызов её телом.
  После этого могут исчезнуть накладные расходы вызова и появиться дополнительные возможности для оптимизации.
12. Использование IR и CFG удобнее анализа исходного текста на C, поскольку они имеют формальную
  и унифицированную структуру, не зависящую от особенностей синтаксиса исходного языка. Это позволяет
  компилятору автоматически находить константные выражения, удалять лишние инструкции и упрощать поток управления.
